## Public DS API

Add and export these four root-level v5 wrappers:

- `RhfTextField`
- `RhfNumberField`
- `RhfSelectField`
- `RhfMultiSelect`

Each wrapper must:

- accept a typed RHF `name` and optional `control`, using the nearest
  `FormProvider` context when `control` is omitted;
- expose RHF `rules`, `defaultValue`, `shouldUnregister`, and `disabled`;
- own the controlled primitive's value, change, blur, field error, and touched
  state rather than allowing consumers to override RHF wiring;
- merge RHF's focus ref with a caller ref aimed at the actual input or visible
  select trigger;
- support label, tooltip, description, required state, stable IDs,
  `aria-invalid`, and combined description/error associations;
- show field errors after touch or a submit attempt with fixed behavior;
- preserve the underlying primitive's styling and test-selector props.

`RhfNumberField` must maintain the consumer-facing `number | ''` value contract
without destroying transient editing states. Its editing state machine is:

| Input buffer                                                          | RHF value while editing                                                                    | On blur                                                                             |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| `''`                                                                  | Commit `''` immediately                                                                    | Keep `''`                                                                           |
| A numeric string with at least one digit, including `1.`              | Commit `Number(buffer)` immediately while retaining the exact buffer                       | Normalize the buffer to the committed number                                        |
| `-`, `.`, or `-.`                                                     | Keep the last committed RHF value and retain the local buffer                              | Restore the last committed display value, or `''` when there was no committed value |
| A string rejected by precision or lexical rules                       | Do not change the buffer or RHF value                                                      | Keep the last accepted state                                                        |
| A programmatic value or RHF reset, including reset to the same number | Replace the local buffer from the external value and make the external value authoritative | N/A                                                                                 |

`min` and `max` remain synchronous editing guards inherited from the existing
`NumberField`; the wrapper also supplies RHF validation rules for programmatic
or default values. They do not change incomplete-buffer or blur resolution.
The wrapper must detect RHF resets even when the committed number is unchanged.
Tests must cover every transition above plus integer, decimal, negative, empty,
min/max, step, reset, and submit behavior.

`MultiSelect` needs only the raw-contract extension required by
`RhfMultiSelect`. Preserve its existing forwarded trigger ref and add a
composite `onBlur` contract: a native trigger blur that merely moves focus into
the open popover must not touch the field, while leaving the closed composite or
each open-to-closed interaction must call `onBlur` exactly once. Apply
`aria-required`, `aria-invalid`, and `aria-describedby` to the visible trigger.
Test keyboard and pointer focus transitions, selection, closing, and ref
attachment. Do not duplicate the multi-select implementation in the wrapper.

## Acceptance criteria

The W3 package is complete only when:

1. The four wrappers are public, typed, documented, accessibility-tested, and
   proven against both RHF control modes.
2. `RhfNumberField` preserves `number | ''`, transient decimal editing, empty
   clearing, validation, submit, and reset semantics.
3. The DS packed artifact and separately published alpha.3 registry artifact
   both expose the same tested API and declarations.
4. Demo-game has no callers of generic local RHF field/FormProvider glue in its
   authored form surfaces and no v4 `ShadcnTable` imports; public GBL
   compatibility exports remain intact pending their own external-consumer
   decision.
5. Demo-game installs and runs against the registry alpha.3 artifact with one
   React/RHF runtime and real browser evidence across all migrated routes.
6. The applicable review gates have passed for the exact final commits.

## Stop conditions

Stop and report the blocker if the dirty GBL snapshot changes during

path cannot be exercised, duplicate React/RHF runtimes remain, or a reviewer
