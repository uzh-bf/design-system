## Source identity and interpretation

Upstream is [shadcn-ui/ui at3d98900](https://github.com/shadcn-ui/ui/tree/3d98900e9b73c45f035f8109e9d41ba6a51685e7),
separate from CLI 4.22.1. Primary roots are

its manifests, and the pinned docs/examples/chart gallery linked below. Source
was read through host gh, cached privately; no upstream code was installed.

There are 63 UI TSX sources, 52 shared local filenames and 11 absent local files.
The UI manifest has a 64th, fileless `form` item; it is accounted for separately.
There are 67 registry examples, 30 block IDs with 106 declared paths, and 80
additional preview files outside those block file lists. Counts identify source
sets, not API/behavior parity. Every item below is source-compared, missing,
retained adaptation, application composition or internal infrastructure.
No source row alone proves keyboard, screen-reader, visual or packed equivalence.
[ADR0008](../docs/adr/0008-radix-compatible-shadcn-scope.md) defines the October24
user-approved scope: official Radix-compatible and backend-independent sources,
compatible auxiliaries, and individually retained official recipes. Excluded
backend-only implementations and parity-only variants stay inventoried but do
not require custom replacements or block GA. Existing contracts and separately
named capabilities remain protected. Inspect imports and dependency closure;
directory membership alone does not establish eligibility.

All 63 UI source identities remain accounted for. The current compound Combobox
is excluded, with the official classic Radix recipe retained separately; the
other 62 sources are candidates for qualification, not 62 proven implementations.
The full 67-example, 30-block and 21-AI-pattern inventories also remain intact,
with excluded portions distinguished from eligible composition requirements.

At the inventory baseline, 52 UI modules were available through `./primitives`;
the component layer brings that public set to 54. Root names may be legacy
wrappers. Keep root compatibility. The existing `form` API belongs to
`./react-hook-form` under ADR0002. No additional public entry is assumed.
Upstream `@/registry` and IconPlaceholder imports are generation aliases: adapt
them to existing public components/icons. The published library must not import
upstream app paths. Local `cn` and scoped Radix packages remain valid adapters;
a wholesale move to the upstream `cn` package or radix-ui umbrella is unnecessary.

  official non-Gregorian import-replacement recipe remains application-owned
  composition qualification; this is not a packaged engine-switching claim.
